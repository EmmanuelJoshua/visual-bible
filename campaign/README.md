# Visual Bible campaign

This folder holds the social campaign for the app: the copy is in [CAMPAIGN.md](CAMPAIGN.md), and a 30-second motion-graphics film is made with [HyperFrames](https://github.com/heygen-com/hyperframes), HeyGen's open-source HTML-to-video renderer.

```
campaign/
  CAMPAIGN.md            hook, key messages, platform captions, hashtags, film structure
  renders/               the finished films (vertical 1080×1920, wide 1920×1080)
  capture/               scripts that film the real app in headless Chrome
    serve.mjs            static server for the Next export (../out)
    lib.mjs              virtual clock, camera helpers, frame recorder
    shots.mjs            the shot list: plinth, dive, Antioch, Babylon, journey, temple build, UI stills
  video/                 HyperFrames project, vertical master (index.html)
    assets/footage/      the captured clips (regenerated by `npm run capture`; not in git)
    assets/stills/       app screenshots used on the end card
    make-wide.mjs        generates video-wide/ from video/index.html
  video-wide/            generated 16:9 project (its assets/ is a symlink to video/assets)
```

Everything is installed locally in `campaign/node_modules`: `hyperframes` 0.9.21, `playwright-core`, `gsap` and a Hebrew font. Nothing was installed globally. Rendering uses the system Chrome and FFmpeg.

## Re-render the films

From `campaign/`:

```bash
npm install
```

```bash
export HYPERFRAMES_BROWSER_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" HYPERFRAMES_NO_TELEMETRY=1
```

```bash
npm run render
```

- `npm run render:vertical` renders `renders/visual-bible-vertical.mp4`.
- `npm run render:wide` regenerates `video-wide/` from `video/index.html`, then renders `renders/visual-bible-wide.mp4`.

Each render takes a few minutes on an M1 Pro. Run `npm run lint` before rendering to check the compositions.

If you skip `HYPERFRAMES_BROWSER_PATH`, HyperFrames downloads its own headless Chrome into `~/.cache` the first time.

## Edit the film

- **Words, timing and transitions** are all in `video/index.html`.
  - Clips are placed with `data-start` / `data-duration` attributes.
  - Motion is one paused GSAP timeline registered as `window.__timelines.film`.
  - Edit only the vertical file; `npm run compose` writes the 16:9 version.
  - Layout differences between the two cuts live in the `.v` / `.w` CSS rules.
- **Preview** in the browser with live reload: `npx hyperframes preview video`.
- **Check single frames** without a full render: `npx hyperframes snapshot video --at 2,8,14`.

## Re-capture the app footage

Re-capture when the app changes or you want new shots. You need a fresh static export first: run `npm run build` in the repo root, which writes `../out`.

Start the server and leave it running:

```bash
npm run serve
```

Then, in another shell:

```bash
npm run capture
```

To re-capture only some shots, name them:

```bash
node capture/shots.mjs antioch babylon
```

**How capture works.** `capture/lib.mjs` launches the system Chrome headless with Metal (`--use-angle=metal`), so WebGL renders on the real GPU. An init script replaces `requestAnimationFrame` and `performance.now` with a virtual clock. Each output frame is exactly one clock step, so camera moves, journey playback, tree sway and build tweens all play at true speed and stay perfectly smooth, however long a frame takes to render.

**Driving the app without changing it.** The camera is driven through the diorama stage, found through React's fibers, so no hook is added to `src/`. Shots are captured as 1920×1920 squares; the vertical cut crops the sides and the 16:9 cut crops the top and bottom, with `object-fit: cover`.

**Adding a shot.** Add a camera path (two poses and an ease) to `shots.mjs`, then reference the clip from `video/index.html`.

**The temple builds** are filmed on `/artifacts`, with the build stage stretched over the whole page.
- `build-v` is 1080×1920.
- `build-w` is 2880×1080, and the 16:9 film shows only its left 1920 px, which puts the temple right of centre and leaves room for the title.

## HyperFrames gotchas (learned making this)

- **No animated CSS `filter` or `clip-path` on anything that contains a `<video>`.** It renders black frames. Use transforms and opacity, or a separate dim layer.
- **Don't put a `<video>` inside an element that has its own `data-start`.** Leave the wrappers untimed; the video's own timing hides it outside its window.
- **One root composition per project folder.** That's why the 16:9 cut lives in `video-wide/`.

## Not included

- **Music and voice-over.** The films are silent so each platform's trending or licensed audio can be added at posting time. To bake in a track, add `<audio src="assets/music.mp3" data-start="0" data-duration="30" data-volume="0.8">` to `video/index.html`.
- **The public URL.** It isn't in the repo, so the captions use a `[link]` placeholder and the end card says "Explore free in your browser".
